# 发布检查清单（作者本机实测）

> 发版前请在本机过一遍。**这份清单存在的理由**：上一轮插件的「设置页整块空白」和
> 「输出途中插话后界面停在上一段」两个问题，都是**发出去之后**才被发现的 ——
> 而它们在本机重载一次就能看出来。
>
> 前置：插件以 `link:` 装进 profile 时，本机代码永远是**最新**的（重启即生效）；
> 但版本号还是旧的，这是正常的。

## 0. 前置

```powershell
# 单元测试（离线）
node --test test/parser.test.mjs test/rss.test.mjs

# 降级路径（离线，桩 fetch）
node test/rss-fallback.smoke.mjs

# 宿主冒烟（真连 status.deepseek.com，约 5–25 秒）
node test/host.smoke.mjs
```

三项都要以退出码 0 结束、`checks passed` 全绿。

## 1. 重启 DSH

宿主半部与浏览器半部都要重载 —— **改完必须重启**，热重载不覆盖这两侧。

重启后：

- [ ] **Loader 装配**：`%APPDATA%\@deepseek-ai\dsh-desktop\logs` 里没有**新增**的崩溃日志
      （旧文件不影响）；`%USERPROFILE%\.dsh\profiles\desktop\package.json` 的
      `dsh.profile.bundles` 里仍有 `dsh-deepseek-official-status`
- [ ] **路由返回 JSON**：浏览器打开
      `http://127.0.0.1:19387/deepseek-official-status/current`
      应看到 `"overall"`、`"via":"rsc"`、`"degraded":false`、`"error":null`、`"failures":0`
- [ ] **头部信号灯**：会话标题右侧出现一颗绿点
- [ ] **控制台无报错**：F12 → Console 无红色错误

## 2. 会话头部（日常主路径）

- [ ] 平时只有一颗**点**，没有文字；鼠标移上去面板展开，移开即收起
- [ ] 面板顶部显示总体状态文案 + 「打开状态页 ↗」可点
- [ ] 「更新于 X」时间合理（不该长期停在「几小时前」）
- [ ] 组件列表齐全（当前应为 5 个：V4 Pro API / V4.1 Flash API / 对话服务 / 上传文件服务 / 搜索服务），
      每个后面有 uptime%
- [ ] 「进行中的事件」在无事件时显示「当前无进行中的事件或维护」
- [ ] 「最近事件」列出已解决事件，带状态与时间

## 3. 插件页配置（`plugins.bundle.config`）

侧栏 **插件 → dsh-deepseek-official-status**：

- [ ] 卡片标题显示 `dsh-deepseek-official-status[官方服务状态]`，描述是中文
- [ ] 描述与「包含的组件」之间出现**配置表单**，三个字段：
      状态页地址（文本）、宿主轮询间隔（毫秒）、单次抓取超时（毫秒）
- [ ] 把「宿主轮询间隔」改成 `15000` 并保存 → **不用重启**，面板里的「更新于」开始按 15 秒刷新
- [ ] 改成非法值（如 `abc` 或 `1`）时给出校验提示，且不会写坏配置
- [ ] 「恢复默认」把字段退回默认值（60000 / 15000）
- [ ] 验完把轮询间隔改回 `60000`

## 4. 降级行为（本机实测需要桩或断网）

若要看降级界面（灰灯 + 橙字提示「组件状态数据源不可用」），需要构造「状态页负载读不到、
但 `/feed.rss` 通」的场景。**发布前若要截图，必须在本机过一遍这一项**。

- [ ] 降级时信号灯是**灰色**，绝不显示绿色
- [ ] 面板显示降级提示，组件区不显示假数据
- [ ] 事件列表仍有内容，且事件标题是**可点链接**
- [ ] 三条路径全挂时：保留上一次快照 + 「更新于」继续走动 + 红字错误提示

## 5. 边界

- [ ] 长时间放着（≥10 分钟）不该出现重复堆叠的定时器或内存增长迹象
- [ ] 断网几分钟再恢复：插件应自行恢复，不需要重启
- [ ] 一如既往：**没有任何情况下**把未知显示成「正常」

## 6. 过完清单之后

- [ ] 同步 `README.md` 里的自检数字（如果里面有写测试数量）
- [ ] 确认 `package.json` 版本号与要推的 tag 一致
- [ ] 交回给发布流程：`git push` → 单独 `git push origin vX.Y.Z`（普通 push **不会**推 tag）
